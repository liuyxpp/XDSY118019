E2: Execute and Verify an Analysis

E2 is an optional extension. Complete E1 first so that your data rules are explicit before you write or run code.

Goal

Write and execute your own reproducible analysis of motion.csv using the rules in motion_notes.md. Produce evidence that distinguishes code written from code actually run.

This package does not include a starter script or numerical answer key.

Choose an Execution Path

Agent Path

Give the Agent this student folder as its working directory. Ask it to read the data and notes, write the required files, run the script, and preserve the actual command and output. The optional AGENTS.md and skills/analyze-motion/SKILL.md files show project instructions that you may inspect and edit. Their presence does not prove that the Agent read them.

After the Agent reports completion, open every output and inspect the run log yourself. A natural-language “done” message is not execution evidence.

Chat-Assisted Path

Ask a chat model to help you design or review a script. Save the code as analysis.py, then run it yourself in a local Python environment. Record your actual command and terminal output. Code shown in chat has not been executed unless you run it.

Local, No-AI Path

Write analysis.py yourself and run it in a local Python environment. The analysis rules and required outputs are the same as in the other paths.

If you have no account and no local Python environment, complete only the offline branch of E1. There is no simulated or teacher-supplied E2 run to claim as your own.

Analysis Requirements

Your script must:

  1. read motion.csv rather than embedding calculated answers;
  2. identify and exclude rows whose position is missing, and record the reason;
  3. preserve time in seconds and convert valid position values from cm to m;
  4. fit an ordinary least-squares straight line that includes an intercept;
  5. report the fitted velocity and initial position with units;
  6. create a plot of the valid data and fitted line with axis labels and units; and
  7. perform transparent checks that you can explain, such as row accounting, finite fitted values, expected output files, and correct plot units.

Do not infer temperature, measurement uncertainty, instrument details, or real experimental conditions. Do not replace the missing position with zero or an invented value.

Required E2 Outputs

Save all four files in your working folder:

  • analysis.py — your reproducible source code;
  • motion.png — the plotted valid data and fitted line, with units;
  • report.md — your completed analysis report template; and
  • run-log.txt — the actual command, standard output, standard error, and exit status from your run.

If execution fails, preserve the real error in run-log.txt and describe the blocker in report.md. Do not invent successful output.

Verification Before Submission

  • Open motion.png and check that the data, line, and axis units are visible.
  • Confirm that report.md agrees with the files and terminal output.
  • Confirm that every reported numerical result came from the executed script.
  • Explain which source note supports each data-handling decision.
  • State what you checked and what remains unknown.

The optional memory/handoff-template.md file can record verified state if you continue later. It is a visible task record, not hidden model reasoning.
